# Q13: 栈和堆有什么区别？ 📦

理解栈（stack）和堆（heap）的区别，是理解 Rust 所有权和性能特征的基础。这两个内存区域各司其职，决定了数据存放的位置和访问效率。

## 🧭 引入与类比

想象一个厨房 🍳：

- **栈**就像操作台面：空间有限，但拿东西极快，按顺序摆放和收拾。
- **堆**就像储物间：空间大，可以放各种大小的东西，但每次去拿都需要走一段路。

## 💡 核心概念图解

### 栈

- 自动管理的内存区域。
- 存储大小已知、生命周期固定的数据。
- 存取速度极快，只需移动栈指针。
- 存储基本类型和函数调用信息。

### 堆

- 动态分配的内存区域。
- 存储大小未知或生命周期复杂的数据。
- 分配和释放需要更多开销。
- `String`、`Vec`、`Box<T>` 等类型的数据存储在堆上。

## 🔧 深入讲解

### Rust 中的体现

```rust
let x = 5;                        // 整数在栈上
let s = String::from("hello");    // String 结构体在栈上，实际字符数据在堆上
let b = Box::new(5);              // 数据在堆上，Box 本身在栈上
```

### 所有权与堆内存

所有权系统确保堆内存有明确的责任人，避免了手动 malloc/free 的繁琐和危险。当栈上的所有者离开作用域，它会自动释放指向的堆内存。

### 性能考量

- **栈分配**：几乎零成本，只需调整栈指针。
- **堆分配**：需要向操作系统申请内存，可能触发页分配，成本更高。
- 对于高频、小对象，尽量放在栈上或使用栈分配的结构。

## ⚠️ 常见误区

- **误区 1**：所有 `String` 都在堆上。
  - ✅ 正解：`String` 的元数据（ptr/len/cap）在栈上，实际字符数据在堆上。
- **误区 2**：栈上的数据一定比堆上快。
  - ✅ 正解：访问已分配的栈数据确实更快，但现代 CPU 缓存也让堆访问效率不低，关键是减少不必要的堆分配。
- **误区 3**：Box 把数据从堆移到栈。
  - ✅ 正解：正好相反，`Box<T>` 把数据放在堆上，栈上只保留指向堆的指针。

## 📝 一句话总结

栈存储固定大小、生命周期明确的数据，访问极快；堆存储动态大小、生命周期复杂的数据，由所有权系统负责安全释放。
