# Q11: Rust 有垃圾回收吗？ ♻️

Rust **没有垃圾回收器（Garbage Collector, GC）**。与 Java、Go、JavaScript 等语言不同，Rust 通过所有权系统、借用检查和 RAII 模式来管理内存。

## 🧭 引入与类比

想象一个图书馆 📚：

- 有 GC 的语言像是有管理员定期巡逻，把没人看的书收走。你不知道他什么时候来，有时会挡住你借书（GC 停顿）。
- Rust 像是你借书时签了一张明确的责任单：书在你手里，你离开时必须归还。没有管理员，也不会突然停顿。

## 🔧 深入讲解

### 内存如何释放？

当一个值的所有者离开作用域时，Rust 会自动调用 `drop` 函数释放资源。这个时机是**确定性的**，不需要运行时 GC 介入。

```rust
{
    let s = String::from("hello");
    println!("{}", s);
} // s 在这里离开作用域，drop 被自动调用
```

### 与 GC 语言的区别

| 特性 | Rust | 带 GC 的语言 |
|------|------|-------------|
| 运行时开销 | 无 GC 暂停 | 可能有 GC 停顿 |
| 内存释放时机 | 确定性 | 不确定 |
| 内存安全 | 编译期保证 | 运行时检查 |
| 循环引用 | 编译期避免 | 需要弱引用或 GC 处理 |

### 优势

- 可预测的性能，没有 GC 导致的暂停。
- 更小的运行时体积。
- 适合系统编程、实时系统、嵌入式等对延迟敏感的场景。

### 代价

- 开发者需要理解所有权和借用规则。
- 某些场景下代码会比 GC 语言更复杂。

## ⚠️ 常见误区

- **误区 1**：没有 GC 就意味着要手动 free。
  - ✅ 正解：Rust 自动调用 `drop`，日常代码完全不需要手动 free。
- **误区 2**：没有 GC 就不安全。
  - ✅ 正解：Rust 在编译期通过所有权和借用检查保证内存安全。
- **误区 3**：Rust 永远不会内存泄漏。
  - ✅ 正解：Rust 能防止大多数泄漏，但 `Rc`/`Arc` 循环引用等仍可能导致泄漏。

## 📝 一句话总结

Rust 通过所有权 + RAII 在没有 GC 的情况下管理内存，释放时机确定、性能可预测，是系统编程和高并发场景的理想选择。
