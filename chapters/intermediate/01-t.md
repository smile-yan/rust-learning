  // 泛型函数：T 是类型参数，PartialOrd 约束保证可以用 > 比较
  // 返回引用 &T 而不是 T，避免移动所有权（T 可能没有实现 Copy）
  fn largest<T: PartialOrd>(list: &[T]) -> &T {
      let mut max = &list[0];
      for item in list {
          if item > max {
              max = item;
          }
      }
      max
  }

  // 泛型结构体：x 和 y 必须是同一类型 T；
  // derive(Debug) 让 {:?} 可以打印
  #[derive(Debug)]
  struct Point<T> {
      x: T,
      y: T,
  }

  // impl 后面的 <T> 是声明泛型参数，
  // 这些方法对所有类型的 Point<T> 都可用
  impl<T> Point<T> {
      fn x(&self) -> &T {
          &self.x
      }
  }

  // 只为 Point<f64> 实现的方法，其他类型的 Point 调不到它
  impl Point<f64> {
      fn distance_from_origin(&self) -> f64 {
          (self.x.powi(2) + self.y.powi(2)).sqrt()
      }
  }

  fn main() {
      let numbers = vec![34, 50, 25, 100, 65];
      // 调用时编译器自动推断 T = i32
      println!("最大值是 {}", largest(&numbers));

      // 同一个函数复用在 char 上，这正是泛型的价值
      let chars = vec!['y', 'm', 'a', 'q'];
      println!("最大字符是 {}", largest(&chars));

      // 整数推断为 i32，这里用的是通用实现里的 x() 方法
      let p = Point { x: 5, y: 10 };
      println!("p.x = {}", p.x());
      println!("点: {:?}", p);

      // f64 类型的 Point 额外拥有 distance_from_origin 方法
      let fp = Point { x: 3.0, y: 4.0 };
      println!("到原点距离: {}", fp.distance_from_origin());
  }

# 泛型 \<T\> 🦀

泛型（Generics）是 Rust 中实现**代码复用**的核心机制之一。它允许我们编写一次代码，就能让这段代码适用于多种不同的类型，而无需为每种类型重复实现。

## 从生活类比开始 💡

想象你有一个可以煮米饭、煮粥、煮汤的锅：锅的形状和加热方式是固定的，但里面放什么食材是“参数化”的。泛型就像是这口锅——它定义了算法或数据结构的“形状”，而具体处理什么类型则由调用者决定。

## 概念图解

同一个 `Point<T>` 模板，可以实例化为 `Point<i32>` 或 `Point<f64>`，极大地减少了重复代码。

## 深入讲解

### 泛型函数

```rust
fn largest<T: PartialOrd>(list: &[T]) -> &T
```

这里 `T` 代表任意类型，但 `PartialOrd` 是一个 **Trait Bound**，它要求 `T` 必须支持比较操作。Trait Bound 让泛型既灵活又安全。

### 泛型结构体与枚举

```rust
struct Point<T> { x: T, y: T }
enum Option<T> { Some(T), None }
enum Result<T, E> { Ok(T), Err(E) }
```

### 为泛型实现方法

你可以为所有 `Point<T>` 实现通用方法，也可以为特定类型（如 `Point<f64>`）实现专门方法，这叫做**专门化实现**。

### 编译期单态化 ✅

Rust 在编译时会为每个具体类型生成对应的代码版本，这个过程叫 **monomorphization**。它保证了零运行时开销——泛型不会比手写重复代码慢。

## 常见误区 ⚠️

- **误区 1**：泛型会带来运行时性能损失。  
  ✅ 正解：Rust 通过单态化在编译期展开，运行时无额外开销。
- **误区 2**：泛型类型可以随意使用任何操作。  
  ✅ 正解：必须通过 Trait Bound 声明类型具备的能力，否则编译器会报错。
- **误区 3**：`Point<T>` 和 `Point<f64>` 是同一个类型。  
  ✅ 正解：它们是经过单态化后的不同具体类型。

## 一句话总结 🦀

> 泛型让代码像模具一样复用，Trait Bound 则确保模具只适用于合格的材料。
