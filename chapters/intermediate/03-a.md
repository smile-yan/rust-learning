# 生命周期 'a 🦀

生命周期（Lifetime）是 Rust 用来保证**引用始终有效**的机制。它通过编译期检查，彻底杜绝悬垂引用（dangling reference）和非法借用。

## 从生活类比开始 💡

想象你借用了朋友的书。这本书的有效期不能超过朋友拥有它的时间——如果朋友把书扔了，你还拿着指向这本书的借条，就毫无意义了。生命周期就是 Rust 用来检查这种“借条是否有效”的抽象。

## 概念图解

![生命周期：借用不能比拥有者活得更长](/images/module1-lifetime-borrowing.svg)

左侧展示了有效借用：引用 `r` 在 `s` 有效期间使用。右侧展示了非法借用：`s` 已经离开作用域被释放，再使用 `r` 会导致编译错误。

![生命周期标注](/images/module1-lifetime-annotation.svg)

`longest<'a>` 的签名表明：返回值的生命周期与输入参数 `x` 和 `y` 中较短的那个一致。

## 深入讲解

### 语法

`&'a str` 表示引用至少存活 `'a` 这段时间。生命周期参数以撇号开头，通常使用小写字母。

### 函数签名

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str
```

这个签名告诉编译器：返回的引用不会比 `x` 或 `y` 中任何一个活得更长。

### 结构体中的生命周期

```rust
struct Book<'a> {
    title: &'a str,
}
```

结构体实例不能比它内部的引用活得更长。

### 省略规则

Rust 有生命周期省略规则（lifetime elision），在简单场景下可以省略标注：

1. 每个引用参数都有自己的生命周期。
2. 如果只有一个输入生命周期，它会被赋给所有输出生命周期。
3. 如果有 `&self` 或 `&mut self`，其生命周期会被赋给所有输出生命周期。

## 常见误区 ⚠️

- **误区 1**：生命周期会改变引用的实际存活时间。  
  ✅ 正解：生命周期只是编译器用来验证引用的标注，不改变运行时行为。
- **误区 2**：返回值生命周期可以比输入参数长。  
  ✅ 正解：返回值只能取输入生命周期中的最小值。
- **误区 3**：生命周期只在函数中需要标注。  
  ✅ 正解：结构体、枚举、impl 块中也可能需要标注。

## 一句话总结 🦀

> 生命周期是 Rust 对“引用何时有效”的编译期证明，让悬垂引用无机可乘。
