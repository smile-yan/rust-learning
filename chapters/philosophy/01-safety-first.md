# 安全优先：编译期保证 🛡️

Rust 最著名的标签之一就是「安全」。但它所说的安全并不是运行时加一层沙箱，而是把大量潜在错误推到编译期解决。这种哲学让 Rust 在不牺牲性能的前提下，显著降低崩溃、内存泄漏和数据竞争的概率。

## 为什么编译期安全更重要？

运行时检查有两个明显缺点：

1. **发现太晚**：bug 可能已经在线上造成损失。
2. **运行开销**：每次检查都要消耗 CPU 周期。

编译期检查则相反：你在写代码时就能拿到精确的错误位置和修复建议，而且这些检查不会生成任何运行时代码。

## 零成本抽象

「零成本抽象」是 Rust 的核心口号之一。它的含义是：高级特性（迭代器、泛型、trait 等）不会带来运行时开销。你写的抽象代码会被编译器优化成与手写底层代码几乎相同的机器码。

这意味着你可以同时拥有：
- **高级语言的表达能力**
- **接近 C/C++ 的运行时性能**
- **编译期的严格安全检查**

## 与 GC 语言的对比

垃圾回收语言通过运行时追踪内存来保证安全，代价是不可预测的暂停。Rust 则在编译期就确定内存归属，释放时机完全可控。

## 一句话总结 ✅

Rust 的安全哲学是：把错误消灭在编译阶段，用类型系统和所有权规则替代运行时的猜测与检查。
