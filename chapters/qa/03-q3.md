# Q3: 什么是所有权？为什么要移动？ 🦀

所有权（Ownership）是 Rust 最核心的内存管理机制。正是凭借它，Rust 在没有垃圾回收器（GC）的情况下，依然能保证内存安全。

## 🧭 引入与类比

想象你有一辆玩具车 🚗。规则很简单：

1. 这辆车同一时间只能属于一个人。
2. 如果你想把它送给别人，你自己就不再拥有它。
3. 当拥有者离开房间时，这辆车会被自动收走。

这就是 Rust 所有权的朴素版本。

![所有权移动示意](/images/module3-ownership.svg)

## 💡 核心概念图解

Rust 所有权有三条铁律：

1. **每个值都有一个所有者**。
2. **同时只能有一个所有者**。
3. **所有者离开作用域，值被丢弃，内存自动释放**。

## 🔧 深入讲解

### 为什么要移动而不是复制？

当把一个堆上分配的值赋给另一个变量时，Rust 选择「移动」（move）所有权，而不是默认深拷贝。原因有三：

1. **避免重复释放** 🚫：如果 `s1` 和 `s2` 都指向同一块堆内存，当它们离开作用域时，`drop` 会被调用两次，导致 use-after-free 或 double-free。
2. **避免昂贵拷贝** 💸：深拷贝大型数据结构（如包含大量文本的 `String`）开销很大。移动只是复制栈上的指针/长度/容量，成本极低。
3. **明确数据生命周期** 📅：所有权移动让「谁负责释放这块内存」变得非常清晰。

```rust
let s1 = String::from("hello");
let s2 = s1; // s1 的所有权移动到 s2
// println!("{}", s1); // ❌ borrow of moved value
```

### 需要复制怎么办？

- 使用 `.clone()` 显式深拷贝。
- 使用实现了 `Copy` trait 的类型，如整数、浮点数、布尔值、字符等。

```rust
let x = 5;
let y = x; // ✅ i32 实现 Copy，不会移动
println!("x: {}, y: {}", x, y);
```

## ⚠️ 常见误区

- **误区 1**：移动会把堆内存从一个地方「搬」到另一个地方。
  - ✅ 正解：移动只复制栈上的元数据（指针、长度、容量），并标记原变量无效，堆数据原地不动。
- **误区 2**：所有赋值都会移动。
  - ✅ 正解：只有没有实现 `Copy` 的类型才会移动；标量类型默认 Copy。
- **误区 3**：所有权让代码变得太复杂。
  - ✅ 正解：初期确实需要适应，但它替代了手动 malloc/free 和 GC 的不可预测停顿。

## 📝 一句话总结

所有权让每一块堆内存都有明确的主人，移动则确保同一时刻只有一个主人，从而在编译期消灭 double-free 和 use-after-free。
